# TMDB 与跨节点聚合

节点的聚合开关同时启用 Provider ID 转换及跨节点搜索。每个目标节点都从原始查询出发，独立应用自己的 `aggregationMode`：

- `tmdb`：用 TMDB 标题和年份搜索，不访问 todb。
- `emos`：转换成 `todbvs`；映射失败则保留原始 Provider ID 查询。
- `auto`：优先 TMDB 标题和年份。元数据查询失败，或首轮媒体库搜索确实为空时，尝试一次 todb。非首页、`Limit=0`、非零总数、鉴权失败均不触发空结果回退。

## 节点凭据

跨节点请求使用目标节点“自定义请求头”中的访问凭据，例如 `X-Emby-Token: <目标节点用户令牌>`。不再将当前节点的客户端令牌、Cookie 或查询串密钥转发给其他节点。建议使用具备所需媒体权限的用户令牌；无需管理员密钥。没有显式凭据的目标节点会被跳过。

本节点仍须先成功返回 200 JSON，且客户端携带鉴权凭据，才能发起列表聚合。目标节点上游负责校验其配置凭据。开启聚合的节点将配置的鉴权头作为一组覆盖客户端鉴权载体，避免混入其他节点的 token；未开启聚合的普通代理保留原有行为。

用户限定查询通过目标节点的 `/Users/Me` 确认对应用户；如目标服务不支持此接口，可在目标节点的 `Authorization` / `X-Emby-Authorization` 中使用包含 `UserId="<目标用户ID>"` 的媒体鉴权头，Worker 会再请求 `/Users/{id}` 验证。无法确认用户时跳过，不移除用户范围。

## 搜索范围与失败处理

`ParentId`、`SeasonId`、`SeriesId`、`Ids` 和剧集列表的剧 ID 必须映射到目标节点。影片/剧优先使用相同 Provider ID，缺失时只接受相同类型、标题及年份的唯一匹配；季按所属剧和季号映射。媒体库视图仅在用户已确认且名称、类型、CollectionType 唯一匹配时映射。无法映射、存在歧义或不支持的本地 ID 条件会跳过该节点，不扩大搜索范围。

每个目标节点的查询（包括身份映射、元数据转换、空结果回退和响应体读取）共享 12 秒预算。单节点失败、401/403/530、超时不影响本节点结果。跨节点请求不自动跟随重定向，避免把目标凭据发送到其他主机。聚合列表不使用本节点元数据缓存，避免缓存命中绕过聚合。

## 缓存、并发合并与 CPU

- TMDB 标题缓存保留 24 小时，todb 映射保留 24 分钟，失败或空结果保留 60 秒。两类缓存分别限制 4096 条，命中更新 LRU；过期按需淘汰。缓存与 single-flight 按 KV 绑定、配置命名空间和有效凭据隔离；TMDB 还区分语言、电影/剧及 ID，凭据轮换立即使用新分区。
- 同一元数据查询的并发请求共享一次加载，两类元数据合计最多 128 个在途任务。聚合上游 JSON 查询另有最多 128 个任务，仅完整 URL（包含用户、范围和分页）、全部请求头、绑定及配置命名空间一致才合并；查询完成或失败即移除，不缓存个性化搜索结果。达到上限时跳过新增查询，保留已有任务和本节点结果。
- 取消请求只停止自己的等待，不中断其他等待者；共享 JSON 查询有独立的 12 秒超时，TMDB/todb 分别为 5/8 秒。元数据响应最多读取 512 KiB，聚合 JSON 最多读取 8 MiB。
- 节点摘要和节点配置复用现有仓库缓存、revision 校验与失效机制；播放版本合并复用已读取的节点密钥，避免重复读 KV。
- 同一聚合请求内，主节点范围元数据和鉴权头复用；回退与合并只解析一次原响应，回退命中后复用已解析对象。todb 用 Map 去重并在入缓存前生成各媒体类型的查询值；条目 ID 前缀按节点生成一次，范围匹配遇到第二个命中即停止。

诊断日志只输出节点名、HTTP 状态、结果数量及固定原因，不输出 URL 查询串、令牌或异常原文：

- `missing_peer_credentials`：目标节点未配置访问凭据。
- `upstream_rejected`：查看同条记录的 HTTP 状态；401/403 需核对凭据及上游权限，530 需检查上游服务。
- `unmapped_user` / `unmapped_scope` / `ambiguous_scope` / `unsupported_scope`：无法安全映射范围。
- `timeout_or_cancelled` / `lookup_failed`：预算耗尽、客户端取消或请求失败。
